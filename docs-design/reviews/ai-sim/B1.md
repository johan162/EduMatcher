# WP-B1 — `s300-sim` live acceptance

Plan: [EduMatcher-AI-Sim-Book-Plan.md](../../EduMatcher-AI-Sim-Book-Plan.md), WP-B1.

## Set-up

Cloud container, 2 vCPU, 8 GB. The real `deployment/docker/entrypoint.sh`
(as the image runs it) against a fresh data directory: `EM_CONFIG=s300-sim`,
`EM_PROFILE=ai-sim`, `EM_RESTART_DEAD=1`, `TZ=Europe/Stockholm`,
`EM_START=2026-10-12T09:28` (simulated Monday; real speed), so continuous
trading starts two minutes in. An observer subscribed to the engine and
`pm-market-sim` PUB sockets wrote one row a minute: symbols traded (per
minute and per 5-minute window), trades, RMS / median / >2 % of
`ln(mid / value)` over all 300 symbols, CPU and RSS per process, disk use.
The first four minutes of continuous trading (the opening burst, while the
swarm's rate controller settles) are excluded from the averages.

## Found and fixed on the way

1. **`pm-api-gwy` ignored `order_retention_sec`** (pre-existing bug).
   `_config_with_overrides` rebuilt the config field by field and dropped
   `order_retention_sec` and `audit_db`, so every API gateway kept finished
   orders for 3600 s whatever the configuration said. Under the swarm that
   grew both gateways by ~120 MB/min. Fixed with `dataclasses.replace`;
   `test_api_gateway_runtime` asserts both fields survive. A mechanical
   check of the six other gateways' `_resolve_config` rebuilds found no
   dropped field.
2. **Bounded caches sized for a classroom**: the API gateways' order cache
   (1 h) and the post-trade gateway's replay journal (24 h) would hold
   gigabytes at this order rate. `s300-sim` sets 300 s and 900 s
   (`mks300.sh`, sim case only; regenerated with the recorded seed — only
   those lines and the generator version changed).
3. **`stats.db` growth**: `order_events` was ~95 % of the file (12 MB/min at
   budget 60). New `pm-stats --keep-order-events-days N` gives order events a
   retention of their own; `ai-sim` keeps an hour of them (0.05 day) and a
   week of trades (`TestRetention`, two new tests).
4. **The passive market maker was the load**: `MM01` produced 83 % of all
   order events (603 k of 728 k in 17 minutes) — it re-quotes whenever other
   traders' orders change whether its sides are covered. `ai-sim` now runs it
   with `--strategy symmetric`: total CPU 84 % → 49 % of a core at a higher
   budget, with the same price quality.

## Memory

With the fixes, the exchange's RSS settles at about 1.05 GB: the two API
gateways plateau at ~420 MB together after their 5-minute retention, the
post-trade gateway at ~80 MB after its 15-minute journal; every other process
is flat at 35–75 MB. The long-run trend is in [B7](B7.md).
