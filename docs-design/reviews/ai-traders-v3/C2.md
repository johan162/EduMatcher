# C2 — `pm-alf-gwy` hardening

Load harness: 600 participants (`~/c2` config), each its own ALF session,
1000 commands/s in total.

| Measure | Result |
|---|---|
| Logon | 600/600 in 2.6 s |
| Orders | 58 150 `NEW`, all acknowledged |
| Ack latency p99 | 18.7 ms (12.4 ms in the C3 re-run) |
| Gateway CPU | 45 % of a core at 1000 cmds/s; idle 0 % |
| Slow-client disconnects | 0 |

Ran 110 s instead of 10 minutes (shell-call limit on the device).

Changes: selectors (epoll/kqueue) loop with the ZMQ notification FDs
(`zmq.Poller` was O(n): 92 % CPU at 600 sessions); dirty-set flush;
housekeeping every 100 ms; `RLIMIT_NOFILE` raised or refuse;
`max_connections` default 1024; `FEED=ORDERS` on `HELLO`; broadcast line
built once; `FILL` carries `SYMBOL`/`SIDE`; `SYMBOLS` reply cached.

Bug fixed: the per-session auth topic was subscribed right before connecting,
so engine replies were lost in logon bursts (39/600 logged on).
